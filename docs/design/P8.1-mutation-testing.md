# P8.1 design: automatic mutation testing

Status: **approved by the owner on 2026-11-27** as recommended (M1–M6). First version covers `raft/` only, with `storage/` and `kv/` as a second step; the nightly scheduled workflow is approved.

## Goal

The eight bug-zoo mutations were chosen by hand, so they may be biased toward what the harness
already catches. P8.1 generates mutants automatically across `raft/` (then `storage/` and `kv/`)
and asks, for each one: does it compile, do the unit tests kill it, does the chaos harness kill
it within K seeds? Survivors are classified (equivalent, liveness-only, or a real gap) and real
gaps get fixed.

Headline number: **mutation score of unit tests alone vs harness alone vs both**, over N mutants,
with every survivor explained in `docs/MUTANTS.md`.

## Design decisions (two options each, with a recommendation)

**M1. How to generate and run mutants.**
(a) Use an existing Go tool (Gremlins, or a go-mutesting fork). They exist, but their maintenance
is uneven across forks, and they are built around `go test`: they cannot also run our harness per
mutant with a seed budget and classify the result.
(b) A small mutator of our own with `go/ast`, applying **one mutant at a time through Go's
`-overlay` flag** (the build reads a mutated copy of one file; the repo is never modified, and
mutants can run in parallel).
**Recommend (b).** Small (a few hundred lines), deterministic, and it plugs straight into the
harness.

**M2. Mutation operators.**
(a) A wide set (constant replacement, swapped arguments, removed function calls, ...).
(b) A fixed, classic set: comparison boundary (`<`↔`<=`, `>`↔`>=`), negation (`==`↔`!=`),
logical (`&&`↔`||`), off-by-one (`+1`/`-1` removed), `if` condition forced `true` / `false`,
`++`/`--` removed, plain `=` assignment statements removed (not `:=`, which would not compile).
**Recommend (b)** for the first version. It is the standard core set and keeps the survivor
analysis manageable (hundreds, not thousands, to explain).

**M3. Harness kill budget K.**
(a) A fixed K for every mutant.
(b) K = 2000 seeds with stop-at-first-failure, then every survivor re-run at 10,000 seeds before it
is called a survivor.
**Recommend (b).** The rarest bug-zoo entry is caught in 3 of 3000 seeds, so 2000 alone would miss
rare ones; re-running only survivors keeps the total time low.

**M4. Liveness (driven by the spike result).**
(a) Count only safety failures as kills, and list "no progress" mutants as liveness-only survivors.
(b) Add a minimal **progress check** to the harness: after the faults stop and the network heals,
the cluster must complete at least one client operation before the run ends; otherwise the run
fails with `Progress`. Report safety kills and progress kills separately.
**Recommend (b).** It turns a real harness blind spot into a checked property. It adds no random
draws, so seeds do not move, but correct code must still pass a full 10,000-seed sweep with the new
check before it is kept (if the settle phase is too short for some seeds, the bound is adjusted and
the reason recorded). This is a small, early piece of P3.6.

**M5. Infinite loops and crashes.**
(a) Let a mutant hang the run.
(b) Run each mutant's tests and harness under a wall-clock timeout (unit tests 60 s, harness 120 s)
and count a timeout or a panic as **killed (timeout / crash)**, a separate category.
**Recommend (b).**

**M6. Where it runs.**
(a) The full set on every push.
(b) On every push, a fixed sample of 20 mutants (chosen deterministically by mutant id) with unit
tests and 500 harness seeds; the full run in a nightly scheduled GitHub Actions workflow, which
writes its report as a workflow artifact.
**Recommend (b).** Keeps CI fast (about a minute) while still running the full set daily.

## How it works

1. **Enumerate.** Walk the package's non-test files with `go/ast` in a fixed order (file name,
   then position). Each mutant gets a stable id `file:line:col:operator`, so results are
   reproducible and one mutant can be re-run with `raftlab-mutants -id ID`.
2. **Compile filter.** Build with the overlay; mutants that do not compile are counted and
   dropped.
3. **Unit tests.** `go test -overlay` on the simulated packages. Fail = killed by unit tests.
4. **Harness.** Build `raftlab-chaos` with the overlay and run K seeds (M3), classify by
   property, including `Progress` (M4) and timeout/crash (M5).
5. **Report.** `results/mutants.json` (every mutant: id, operator, diff line, unit verdict,
   harness verdict and first failing seed) and a summary table. Scores: unit only, harness only,
   both, neither.
6. **Survivors.** Each is classified in `docs/MUTANTS.md`: *equivalent* (with a one-line argument
   why behaviour cannot change; equivalence is undecidable in general, so this is a manual
   judgement), *liveness-only*, or *real gap*. Real gaps get a new unit test or harness check, and
   the run is repeated.

## Files

- `mutate/`: the AST mutator (enumeration, operators, overlay files).
- `cmd/raftlab-mutants/`: runner and report.
- `harness/`: the `Progress` check (M4).
- `.github/workflows/ci.yml` (sample) and a new nightly workflow.
- `docs/MUTANTS.md`, `results/mutants.json`, README section.

## Tests (to be written before the code)

1. **Operators produce the intended change and still parse:** for a fixture file, each operator
   yields exactly one changed node, and the result type-checks where expected.
2. **Enumeration is deterministic:** two enumerations of the same package give the same ids in the
   same order.
3. **The overlay never touches the repo:** after running mutants, the working tree is unchanged.
4. **End to end on a tiny fixture package** with a known killed mutant and a known equivalent one.
5. **Progress check:** a mutant that blocks elections (the spike's `isUpToDate` change) fails with
   `Progress`, and correct code passes 10,000 seeds with the check on.

## Effort and risk

About 15–25 build hours. Risks: classifying survivors by hand takes time (mitigated by the small
operator set); a progress bound that is too tight would fail correct seeds (mitigated by the 10,000-
seed check in M4); total run time (measured, then sampled in CI).
